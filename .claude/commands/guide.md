# 작업 완료 가이드 생성 커맨드

현재 대화에서 수행한 작업을 분석하여 대상에 맞는 가이드를 생성합니다.

**사용법:** `/guide`

---

## 진행 순서

### 1. 대상 선택
AskUserQuestion으로 가이드 대상을 질문:
- **front** - 프론트엔드 개발자 (API 연동 가이드)
- **back** - 백엔드 개발자 (기술적 상세 가이드)
- **po** - 기획자/비개발자 (비즈니스 관점 요약)

### 2. 현재 대화 분석
- 생성/수정된 파일 목록
- 새로 추가된 API 엔드포인트
- 변경된 비즈니스 로직 / 데이터 모델

### 3. 대상별 가이드 생성

---

## Front (프론트엔드 개발자용)

### 포함 내용:
1. **작업 요약**
2. **API 명세** — URL, Request Body, Response Body(ApiResponse 래퍼), 에러 코드
3. **연동 예시** (TypeScript fetch/axios)
4. **주의사항** — 필수 파라미터, 유효성 규칙

### 출력 형식:
```markdown
## API 명세

### {API 이름}
- **URL:** `{METHOD} /{path}`
- **인증:** 필요 / 불필요 (`Authorization: Bearer ...`)

**Request:**
\`\`\`json
{ "field": "value" }
\`\`\`

**Response (성공):** — 모든 응답은 ApiResponse 래퍼
\`\`\`json
{
  "success": true,
  "code": "...",
  "message": "...",
  "data": { "id": 1, "field": "value" }
}
\`\`\`

**에러 코드:**
| 코드 | 메시지 | 상황 |
|------|--------|------|
| 400 | {메시지} | 입력 검증 실패 |
| 404 | {메시지} | 리소스 없음 |

**연동 예시:**
\`\`\`typescript
const res = await axios.post('/path', { field: 'value' });
const data = res.data.data; // ApiResponse.data
\`\`\`
```

## Back (백엔드 개발자용)

### 포함 내용:
1. **작업 요약** (배경/목적)
2. **아키텍처 변경** — 추가된 클래스, 레이어별(Controller / CommandService·QueryService / Domain)
3. **기술적 고려사항** — 트랜잭션, 예외 처리, 성능(N+1), 동시성, 외부 I/O 위치
4. **테스트 현황** — 추가된 케이스
5. **향후 개선 제안**

### 출력 형식:
```markdown
## 변경된 파일
| 파일 | 변경 내용 |
|------|----------|

## 아키텍처 상세
### Controller
### Service (Command / Query)
- 트랜잭션: {방식}
### Domain (Entity / Repository)

## 기술적 고려사항
- 예외 처리 / 성능 / 동시성 / 외부 I/O

## 테스트
| 테스트 클래스 | 케이스 | 검증 내용 |
```

---

## PO (기획자/비개발자용)

### 작성 원칙:
- 개발 용어 금지 (API, 엔드포인트, 파라미터 등)
- 기능/사용자 시나리오 관점으로 설명

### 출력 형식:
```markdown
## 한줄 요약
{비개발자도 이해할 수 있는 요약}

## 무엇이 바뀌었나요?
- "이제 사용자가 리뷰에 좋아요를 누를 수 있습니다"

## 사용자 흐름
**이전:** ...
**이후:** ...

## 확인이 필요한 사항
- {QA 포인트 - 비개발 용어로}
```

---

## 공통 주의사항
1. **현재 대화에서 실제로 작업한 내용만** 포함 (추측 금지)
2. 확인되지 않은 내용은 "확인 필요"로 표시
3. 복사하여 바로 쓸 수 있도록 마크다운 형식 준수

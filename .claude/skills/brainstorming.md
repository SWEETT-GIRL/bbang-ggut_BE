# Brainstorming

코드를 작성하기 전에 반드시 설계를 먼저 하고 승인을 받는다.

## 핵심 규칙

**Hard Gate:** 설계를 제시하고 사용자의 승인을 받기 전까지는 절대로 구현 코드를 작성하거나 스캐폴딩하거나 어떤 구현 행동도 해서는 안 된다.

## 프로세스 (9단계)

1. **프로젝트 컨텍스트 탐색** — 기존 파일, 문서, 커밋 히스토리 확인
2. **시각적 보조 제안** — 다이어그램이 도움될 경우 제안
3. **명확화 질문** — 한 번에 하나씩 질문 (복수 질문 금지)
4. **2~3가지 접근법 제안** — 각각의 트레이드오프 포함
5. **설계 섹션 발표 + 승인 게이트** — 섹션별로 승인 받기
6. **설계 문서 작성** — `docs/superpowers/specs/` 에 저장
7. **스펙 자기 검토** — 품질 확인
8. **사용자 스펙 검토**
9. **구현으로 전환** — `writing-plans` 스킬 호출

## 핵심 원칙

- 질문은 **한 번에 하나만** (사용자 압도 방지)
- **객관식 선택지** 우선 활용
- 각 컴포넌트는 **단일 책임**, **명확한 인터페이스**
- "간단한 프로젝트"도 반드시 설계 승인 필요

## 주의

"간단한" 프로젝트일수록 검토되지 않은 가정으로 인해 재작업이 가장 많이 발생한다.

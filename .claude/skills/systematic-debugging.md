# Systematic Debugging

버그, 테스트 실패, 예상치 못한 동작을 만났을 때 근본 원인을 먼저 찾은 후 수정한다.

## 핵심 원칙

**"근본 원인 조사 없이는 수정 없다"**

## 4단계 프로세스

### Phase 1: 근본 원인 조사

- 에러 메시지를 정확히 읽기
- 일관되게 재현 가능한지 확인
- 최근 변경 사항 검토 (`git log --oneline -10`)
- 스택 트레이스 전체 읽기
- 데이터 흐름 추적

### Phase 2: 패턴 분석

- 작동하는 유사한 코드 찾기
- 참고 구현과 비교
- 차이점 파악
- 의존성 이해

### Phase 3: 가설 수립 및 테스트

- **단일 가설** 수립
- 최소한의 변경으로 테스트
- 계속 진행 전 검증

### Phase 4: 구현

- 먼저 실패 재현 테스트 작성
- 단일 수정 구현
- 수정 검증
- 3회 이상 같은 방식으로 실패 시 → 아키텍처 재검토

## Spring Boot 디버깅 명령

```bash
# 상세 로그로 테스트
./gradlew test --info

# 특정 테스트만
./gradlew test --tests "sweetgirl.croissant.패키지.클래스명"

# 스택 트레이스 포함
./gradlew test --stacktrace
```

## 중단 신호

"빠른 수정", "그냥 한번 해보자", "여러 개 동시에 변경" 같은 생각이 들면 → Phase 1로 돌아가기

## 데이터

체계적 접근: 15~30분 / 무작위 시도: 2~3시간

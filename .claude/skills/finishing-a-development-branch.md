# Finishing a Development Branch

개발 작업을 완료할 때 테스트 검증 → 환경 감지 → 옵션 제시 → 실행의 구조적 프로세스를 따른다.

## 프로세스

### Step 1: 테스트 검증

```bash
./gradlew test
```

테스트가 실패하면 중단하고 수정한다. 모든 테스트가 통과할 때만 계속한다.

### Step 2: 환경 감지

```bash
git status
git branch
git log --oneline -5
```

현재 상태: 일반 레포 / 네임드 브랜치 워크트리 / detached HEAD

### Step 3: 베이스 브랜치 파악

```bash
git merge-base HEAD main
```

### Step 4: 옵션 제시

**일반 레포 / 네임드 브랜치 워크트리 (4가지 옵션):**

1. 로컬에서 베이스 브랜치로 머지
2. 푸시 후 Pull Request 생성
3. 브랜치를 현재 상태로 유지
4. 이 작업 폐기

**Detached HEAD (3가지 옵션):**

1. 새 브랜치로 푸시 후 PR 생성
2. 현재 상태로 유지
3. 이 작업 폐기

### Step 5: 선택 실행

- **옵션 1:** 머지 → 테스트 검증 → 정리 → 브랜치 삭제
- **옵션 2:** 브랜치 푸시 → PR 생성
- **옵션 3:** 브랜치와 워크트리 유지
- **옵션 4:** "discard" 타이핑 확인 후 삭제

## 핵심 규칙

- 테스트 검증은 절대 건너뛰지 않는다
- 폐기 시 반드시 타이핑 확인 요구
- 직접 생성한 워크트리만 정리 (`.worktrees/`, `worktrees/` 하위)
- 워크트리 내부에서 삭제 명령 실행 금지

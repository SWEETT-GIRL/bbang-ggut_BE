# Test-Driven Development (TDD)

## 핵심 원칙

"테스트가 실패하는 것을 직접 보지 않았다면, 그 테스트가 올바른 것을 테스트하는지 알 수 없다."

## Iron Law

**실패하는 테스트 없이는 프로덕션 코드를 작성할 수 없다.** 테스트 없이 먼저 작성된 코드는 예외 없이 삭제해야 한다.

## Red-Green-Refactor 사이클

**RED:** 기대 동작을 보여주는 최소한의 실패 테스트 작성

**RED 검증:** 테스트 실행 → 예상한 에러 메시지로 실패하는지 확인

**GREEN:** 테스트를 통과시키는 최소한의 코드만 작성

**GREEN 검증:** 해당 테스트 통과 + 다른 테스트도 여전히 통과하는지 확인

**REFACTOR:** 테스트를 통과시키면서 코드 정리

**반복:** 다음 기능으로 이동

## Spring Boot 프로젝트 적용

```bash
# 테스트 실행
./gradlew test

# 특정 테스트만 실행
./gradlew test --tests "sweetgirl.croissant.*"
```

## 좋은 테스트 조건

- 하나의 동작만 테스트
- 명확하고 설명적인 이름
- 실제 코드 사용 (mock 최소화)
- 원하는 API를 명확히 표현

## 완료 전 체크리스트

- [ ] 모든 함수에 테스트 존재
- [ ] 각 테스트가 구현 전에 실패했음을 확인
- [ ] 실패가 예상한 이유(기능 누락)였는지 확인
- [ ] 모든 테스트가 통과하며 깔끔한 출력

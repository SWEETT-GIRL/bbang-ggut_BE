# 자동완성 인기순 정렬 + 급부상 구조 정리

브랜치 `feat/trending-ranking-cleanup` · base `develop-v2` (Redis CD·배치 분리가 여기 있다)

## 목표
'한'을 치면 지역이 앞자리를 차지하지 않고 찾는 사람이 많은 가게가 먼저 보인다. 급부상은 표시 없이 정렬에 녹인다.

## 정렬 규칙 (접두 일치 가게 기준)
급부상(최대 2) → 인기 가게(`popularity_score` 5 이상, 높은 순, 최대 5곳, 가게당 한 줄) → 지역 → 나머지 기존 순서.
- `AUTOCOMPLETE_POPULARITY_ORDER_ENABLED`: 인기순(API 서버). 주간 인기도 점수만 써서 Redis 불필요.
- `TRENDING_ENABLED`: 신호·순위표·급부상 노출·평소 수준 배치. Redis 필요.
- 둘 다 끄면 기존 순서. 응답 필드 변경 없음.

## 구조 정리
- 순위표를 `trend:ranking`(JSON, TTL = 갱신 주기×3, 기본 90분) 키 하나로 합쳤다. 갱신이 멈추면 만료되어 인기순으로 돌아간다.
- 신호 기록을 Lua 한 번으로 묶었다(`trending-record.lua`). 판정만 남거나 TTL 없는 키가 남지 않는다.
- Redis 를 못 읽으면 직전 순위표를 최대 60분 쓴다.

- 순위표 갱신 주기를 5분 → 30분으로 늘렸다(`store.trending.refresh-interval`). 신호 하루 약 190건 규모라 5분은 대부분 같은 결과였다.

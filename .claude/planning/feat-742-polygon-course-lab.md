# #742 폴리곤 소속과 도시 전체 추천 후보 검증

브랜치: `feat/742-polygon-course-lab` · base `origin/dev@7b6e651d` · 2026-10-12

이 파일이 현재 브랜치의 통합 Spec/Plan이다. 이전 여러 원 확장 [Spec](../../docs/planning/course-area-coverage-742-spec.md)·[Plan](../../docs/planning/course-area-coverage-742-plan.md)은 비교 대안의 기록으로 보존한다.

## 0. 설계 방향

- 사용자가 선택한 도시의 가게를 고정 원으로 잘라 취향 비교 기회를 잃는 문제를 해결한다.
- 공식 폴리곤은 지역 소속 판정에 사용한다. 동 경계를 코스 이동 제한으로 쓰지 않는다.
- 성남의 시·구·동과 세종의 단계 생략을 `region_1st/2nd/3rd`의 동일한 위치에 억지로 맞추지 않는다. 원형 코드와 앱 scope 관계를 별도로 유지한다.
- 운영 데이터 수정 전에 로컬에서 검증한다. Gemini 이유 생성은 기존 경로를 활용한다.
- 코드 구현·검증은 개발 작업으로 진행하고 사용자는 이동 허용 범위·재추천 경험 같은 제품 기준을 판단한다. 거리 상한은 비교 결과를 바탕으로 제안하며 실험값을 자동 확정하지 않는다.

## 1. 요구사항 (Spec)

### 이번 로컬 검증 범위

1. 공식 출처·기준일·해시·좌표계를 남기고 원본 경계와 복구 후보를 분리한다.
2. 시범 4개 도시를 시작으로 전국 가게 소속을 검증한다. 원본 무효 코드·도형은 임의로 추정하지 않는다. 법정 읍면동 소속과 앱 지역 범위의 확정 여부를 구분한다.
3. 수원·성남·고양에서 A 현재 방식 / CITY_TOP15 단순 확대 / D 여러 출발점 / D_TIGHT 총거리 제한을 동일 입력으로 비교한다.
4. 점수 SQL과 A의 코스 생성은 기존 코드를 재사용한다. 새 알고리즘은 랩 테스트에만 둔다.
5. 후보 수, 완성률, 실제 선택 범위, 공통 취향·종합 점수, 총거리·최대 구간·퍼짐, 계산 시간을 남긴다.
6. 동일한 가게 제외 조건, 중복 방지, 1~6곳 요청 범위 중 1·4·6곳 사례를 검증한다.
7. 회원 데이터를 사용하는 대신 초기 비교에는 공개 가능한 합성 입력을 쓴다. 실제 만족도·운영 속도 검증으로 표현하지 않는다.

### 실제 서비스 연결 전 추가 요구사항

- 버전 있는 공식 소속 및 앱 scope 매핑을 저장하고 신규·좌표 변경 가게를 갱신한다. 기존 지역 표시 문자열은 호환을 유지한다.
- 요청의 도시 scope와 생성한 근거리 코스 scope를 구분한다. 기존 `areaId`를 임의의 동적 동네로 가장하지 않는다.
- 기록·담은 장소·이전 노출 제외, 동일 시트 재사용, 동일 동네 재추천, 다음 동네 이동을 일관된 범위에서 처리한다.
- 기존 API 응답 필드 삭제/이름 변경 없이 구현 가능한 계약부터 검토한다. 필요 시 추가 필드 및 앱 지원 범위를 명시한다.
- 코스 구간·총거리 상한, 기존 장소와의 연결 규칙, 도로 단절 검수 기준을 확정한다.
- 운영 경계 변동분, 프로필 스냅샷, 실제 사용자 취향과 이력, SQL과 전처리 포함 지연을 확인한다.
- 기능 플래그로 기존 방식 복귀가 가능해야 하며 추천 결과에 알고리즘·경계·scope 버전을 남긴다.

### 검증과 결론

[로컬 비교 결과](../../docs/reports/polygon-course-comparison-20261012.md)를 기준으로 판단한다. 단순 도시 top-15는 4곳 완성 40/102, 6곳 10/102로 부족했다. D_TIGHT는 각각 102/102이며 취향 점수는 평균적으로 개선됐지만 일부 입력은 하락했다. 총거리 제한을 포함한 후보 탐색을 다음 설계 대상으로 삼는다.

추천 API·서비스·DB 마이그레이션은 아직 변경하지 않았다. 이번 결과를 곧바로 운영 알고리즘 적용 완료나 #742 완료로 취급하지 않는다.

후속 [실제 프로필 비교](../../docs/reports/polygon-member-comparison-20261012.md)에서 방문 기록 제외와 고정 장소 연결을 포함했다. D_HYBRID는 D_TIGHT 대비 324건 중 21건 점수가 높고 나머지는 같았다. 재추천은 실제 API 재현이 아닌 같은 범위의 모의 실험이다. 총거리·첫 연결 제약을 적용하면 일부 CONTROL 대비 점수는 낮아질 수 있다.

노션 정리: [폴리곤 기반 개인화 코스 추천 개선과 검증](https://app.notion.com/p/3f7f1bb7a95a817a8a67e4c5402fa907). 개인 초안이며 회원별 입력·경로는 포함하지 않는다.


### 전국 지역 기반 검증 후속

[전국 감사 결과](../../docs/reports/region-polygon-nationwide-20261012.md): 읍면동 기준표 5,067개 모두 경계가 있으며, 추천 적격 37,812곳 중 37,767곳이 단일 법정코드다. 화성 능동은 두 구 코드의 동일 도형으로 적격 29곳이 복수 매칭되지만 화성시 소속은 같다. 앱 지역까지 확정 가능한 적격 가게는 37,796곳이다. 남은 복수 앱 지역 5곳·미매칭 11곳과 표시 불일치 69곳은 별도 검수 대상으로 유지한다.

- 법정코드 상태와 앱 지역 상태를 분리한다. 복수 하위 코드가 같은 도시에 속하면 도시 소속만 확정할 수 있다.
- 판정에 사용한 좌표·경계·기준표·투영 버전을 저장한다. 신규/좌표 변경/경계 변경에 동일 판정 절차를 사용한다.
- 가까운 경계로 자동 이동하거나 기존 region 필드를 덮어쓰지 않는다. 공식 변동분·독립 법정코드 근거로 예외를 검수한다.
- 순서: 전국 감사(완료) → 예외 근거 보강 및 소속 저장 설계 → 로컬 갱신/후보 조회 검증 → API 연결 → 시범 반영.

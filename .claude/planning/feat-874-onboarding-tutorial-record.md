## Spec

### 10/8 확정: 서버 템플릿·어드민 관리

- 목표: 사진·가게·태그·예시 평가·한 줄 평·기록 메모·쌓을 빵을 서버가 제공하고 앱은 기본 선택 상태에서 다음만 눌러 완료한다.
- 사진은 UUID 키로 S3에 불변 업로드하고 CDN으로 조회한다. 앱 번들·API 정적 파일 우회 경로를 사용하지 않는다.
- 어드민에서 사진 업로드, 메타데이터 편집, 새 버전 초안 저장, 미리보기, 발행/노출 중단을 지원한다. 수정은 새 버전 생성이며 기존 버전과 사용자 기록은 덮어쓰지 않는다.
- DB의 템플릿 버전별 본문은 불변이다. 단일 카탈로그 행을 잠가 활성 버전을 바꾸며 과거 발행본으로 시작한 체험은 해당 버전으로 완료할 수 있다.
- 전용 완료 요청은 templateCode와 eatenAt만 필요하다. 기록의 내용과 사진은 서버 발행본에서 복사해 고정한다. 완료 후 기존 부분 수정·삭제 정책은 유지한다.
- 관리자 API는 X-Admin-Key를 필수로 검증하며 키 미설정 시에도 차단한다. 사용자 토큰만으로 관리할 수 없다.
- S3 업로드는 If-None-Match:* 서명 헤더를 사용해 기존 파일 덮어쓰기를 방지한다. 발행 시 key/type/size/업로드 존재를 검증한다.
- Plan: 템플릿 DTO/엔티티/저장소/마이그레이션 → 관리 CQRS와 업로드·발행 API 및 테스트 → 사용자 상태·완료 API 연결 → 앱 자동 기본값·CDN 연결 → 어드민 편집 UI·테스트 → 전체 검증 → 기능별 커밋, 저장소별 최종 push.
- 기존에 제안한 retireDuplicateTutorial의 JPA 전환은 이 변경과 분리한다. 운영 S3 업로드·DB migration·배포는 실행하지 않는다.

### 문제와 가설

사용자가 사진이 없어서만 멈추는 것이 아니라, 어떤 사진을 골라야 하는지와 기록하면 무엇이 달라지는지 몰라 멈춘다는 가설이다. 기존 세계관 소개는 유지하면서 실제 작성 화면에서 미리 선택된 재료를 다음 버튼으로 확인하고 홈의 빵탑 성장까지 연결한다.

튜토리얼 완료를 첫 일반 기록 전환으로 세지 않는다. 과거 공유 수치 8.2%·23%는 재조회한 기준선이 아니며, 상관관계를 기록의 인과효과로 해석하지 않는다. 313명/317명 등 기간과 분모가 다른 퍼널을 섞지 않는다.

### 확정된 사용자 여정

1. 기존 세계관 소개 카드 4장을 유지한다. 읽거나 건너뛴 뒤 카카오·Apple OAuth 버튼을 주요 행동으로 보여주고 먼저 둘러보기는 작은 보조 행동으로 둔다.
2. 가입 또는 둘러보기에서 기존 필수 약관 동의를 유지한다. 체험 뒤로 약관을 옮기지 않는다.
3. 첫 친구를 만나고 실제 홈에 도착한다. 준비 완료·빈 기록·서버 활성화·필수 동의·미완료 조건에서 튜토리얼 초대가 자동으로 열린다.
4. 기존 RecordFlow에서 사진 → 가게 → 빵 태그 → 평가 → 날짜·메모를 경험한다.
5. 서버가 준비한 빵을 확인하고 쌓기 버튼으로 전용 API에 저장한다. 서버 성공 전에는 완료·보상을 표시하지 않는다.
6. 빵탑에 쌓이는 연출을 보고 실제 홈에서 기록 1개와 빵탑 1개를 확인한다. 중간 빵카드는 없다.
7. 홈으로 돌아온 뒤 알림 허용 권유를 연결한다. 거절해도 기록과 보상은 유지한다.

### 준비된 재료

- 사진: 어드민에서 빵과 시작 캐릭터 빵댕이(dog)가 함께 있는 사진 1장을 업로드한다. 사용자 앨범 권한·업로드는 불필요하다.
- 가게: 서버 제공 이름이 이미 선택돼 있다. storeId/regionKey/menuId는 null이며 가짜 Store 행을 만들지 않는다.
- 태그: 사진 위 서버 지정 위치·스타일에 빵 이름표가 미리 붙는다.
- 평가·한 줄 평·메모: 서버 발행본의 체험용 예시를 기존 작성 화면에 채운다. 체험 중 추가 입력 없이 다음으로 진행한다.
- 쌓을 빵: 서버가 croissant / melonpan / soboro / bagel / anpan 중 기본값을 제공한다.
- 템플릿: UUID 버전, 불변 DB 본문, S3 사진 key. 앱은 기존 buildCdnUrl로 사진을 읽는다.
- 최초 발행본은 자동 생성하지 않는다. 관리자 업로드·발행 전에는 튜토리얼을 노출하지 않는다. 기존 번들/static 이미지 파일은 삭제 확인 전 보관하되 런타임에서 사용하지 않는다.

일반 기록의 사진 필수와 게스트 쓰기 제한은 그대로 유지한다. 튜토리얼만 서버가 정한 재료로 저장한다.

### API 계약

모든 튜토리얼 API는 게스트 또는 회원 JWT가 필요하다. 인증 없는 공개 쓰기는 없다.

| API | 역할 |
| --- | --- |
| GET /bread-records/tutorial | enabled, templateCode(nullable), template(nullable), towerBreads, completed, recordId, recordDeleted |
| POST /bread-records/tutorial | templateCode, eatenAt만 요청. 첫 완료 201, 재요청 200 |
| PATCH /bread-records/tutorial/{recordId} | 소유자 메모·평가·쌓을 빵 수정 |
| 기존 기록 조회·삭제 | recordType 포함 조회 및 소유자 삭제 |

서버는 발행본의 사진 key·가게·빵 이름·평가·메모·좌표·빵 종류를 기록에 복사하고 비공개로 고정한다. 필수 약관 3종과 제재·계정 활성 상태도 서버에서 검증한다. 기능 flag 기본값은 false이며 비활성화 뒤에도 기존 완료 응답과 기록 편집·삭제는 유지한다.

관리 API는 `/api/admin/tutorial-templates`의 GET(최근 100개 버전), POST(새 초안), POST `/upload-url`, POST `/{code}/publish`, POST `/stop`이다. 발행·중단에는 `expectedActiveCode`를 보내고 동시 변경 시 409를 반환한다. 노출 중단은 이전 발행본 완료를 막지 않으므로 긴급 전체 중단은 tutorial.enabled=false를 사용한다.

### recordType 타입과 이력 호환 정책

- 엔티티·기록 응답·월간 원천 스냅샷에서 동일한 `RecordType` enum을 사용한다.
- JSON 값은 기존 문자열 `NORMAL`/`TUTORIAL` 그대로이며 DB `VARCHAR + CHECK`는 변경하지 않는다.
- 과거 스냅샷의 필드 누락·null은 NORMAL로 정규화한다. 알 수 없는 문자열·숫자는 기존 SOURCE_HISTORY_UNAVAILABLE 오류로 집계를 중단한다.
- 원천 조회 전용 mapper에서 미지의 enum을 null로 바꾸는 옵션을 끄고 숫자 enum 변환도 차단한다. 전역 mapper 설정은 변경하지 않는다.
- 월간 집계는 TUTORIAL이 아닌 값 전체가 아니라 NORMAL만 허용한다. JSON 호환 및 과거/무효 이력 회귀 테스트로 검증한다.

### 게스트 승격과 이관

- 신규 소셜 가입: 동일 memberId 승격으로 기록과 완료 이력 유지.
- 기존 계정 로그인: 두 회원을 ID 순서로 잠근 뒤 대상 계정 완료 이력을 우선한다.
- 대상 미완료: 기록과 이력을 함께 옮긴다.
- 대상 완료·삭제 이력 존재: 게스트 중복 기록을 비활성화하고 대상 완료 이력을 유지한다.
- 닫히거나 이미 승격한 게스트를 다시 이관하지 않는다.
- 게스트 계정당·최종 회원 계정당 1회 보장이다. 재설치로 신원이 사라지는 경우까지 기기당 영구 1회라고 약속하지 않는다.

### 집계 경계

| 소비처 | 튜토리얼 처리 |
| --- | --- |
| 내 기록 목록·홈 빵탑·세계관 성장 | 포함 |
| 실제 가게 방문·지역·먹은 빵 통계 | 제외 |

사진·메모 원문을 분석 이벤트에 보내지 않는다. 기존 RecordFlow 단계 이벤트는 tutorial_ 접두어와 record_type으로 분리하고 별도 onboarding_tutorial_started/completed/save_failed를 남긴다.

### 알림 범위

성장 미션이나 편지를 새로 만들지 않는다. 이번 범위는 실제 저장·보상 확인 후 기존 권한 권유 연결이다. **D1~D7 꿀팁 콘텐츠·예약 발송은 미구현**이다. 권유 문구에서도 꿀팁은 준비 중임을 알리고 현재 제공하는 알림만 설명한다. 개발 preview는 저장과 권한 요청을 하지 않는다.

### 자동 검증 범위

BE 전체 테스트 2,191개 중 실패 0·오류 0·스킵 1. PostgreSQL 테스트는 일반 실행에서 제외되는 lab 태그로, localhost:5432 테스트 DB의 UUID 스키마에만 데이터를 만들고 정리한다. 공개/가게 연결 금지, 활성 기록 중복, 삭제된 완료 이력의 병합, 월간 보고서 제외, 새 템플릿 카탈로그 migration을 검증한다. 이 검증을 실제 OAuth 또는 앱 전체 통합 테스트로 표현하지 않는다.

관리 API WebMvcTest의 관리자 키·입력·409 충돌, 키 미설정 로컬 503, 템플릿 repository 잠금/발행 유지 테스트를 포함한다. 어드민은 프로덕션 빌드 및 모델/API 5개 테스트를 통과했고 앱은 TypeScript·변경 파일 ESLint·iOS export·기존 사진 회귀 6개 테스트를 통과했다. 브라우저에서 로컬 어드민의 세계관→홈 튜토리얼 연결 화면을 확인했다. 실제 S3 업로드·CDN 노출·발행→앱 저장 통합 QA는 배포 후 남아 있다.

### 배포·롤백

1. BE main 기반 PR과 FE PR을 함께 검토한다. 서버·DB 배포와 앱 배포는 PR 생성과 별개다.
2. 서버 migration/API가 준비된 개발 환경에서 먼저 켠다. cd-staging에 tutorial.enabled=true를 추가하되 실제 배포는 아직 하지 않았다.
3. 현재 개발 서버가 계약을 지원하지 않으면 초대는 숨긴다. 일반 생성 API로 우회하거나 가짜 성공을 표시하지 않는다.
4. 운영 flag는 기본 false로 유지한다. 스키마·S3/CDN·앱 호환 및 QA 후 활성화한다. S3 PUT CORS에 어드민 origin, Content-Type, If-None-Match가 허용돼 있어야 한다.
5. 되돌릴 때 신규 생성 flag만 끄고 저장된 기록·완료 이력은 보존한다.
6. main과 dev는 분기 이력이 다르다. main 기반 결과물을 공유 dev에 덮어씌우지 않고 개발 배포 시 dev 기준 통합을 별도 확인한다.

현재 로컬 앱 설정은 개발 API(bbang-ggut.site)다. .env.local은 PR에 포함하지 않는다. 운영 DB 변경·서버 배포·푸시 발송은 이 검증에서 수행하지 않았다.

## Spec

### 문제와 가설

사용자가 사진이 없어서만 멈추는 것이 아니라, 어떤 사진을 골라야 하는지와 기록하면 무엇이 달라지는지 몰라 멈춘다는 가설이다. 수동적인 세계관 소개 대신 기존 작성 화면에서 준비된 재료를 직접 선택하고 홈의 빵탑 성장까지 연결한다.

튜토리얼 완료를 첫 일반 기록 전환으로 세지 않는다. 과거 공유 수치 8.2%·23%는 재조회한 기준선이 아니며, 상관관계를 기록의 인과효과로 해석하지 않는다. 313명/317명 등 기간과 분모가 다른 퍼널을 섞지 않는다.

### 확정된 사용자 여정

1. 기존 세계관 소개 카드 4장을 유지한다. 읽거나 건너뛴 뒤 카카오·Apple OAuth 버튼을 주요 행동으로 보여주고 먼저 둘러보기는 작은 보조 행동으로 둔다.
2. 가입 또는 둘러보기에서 기존 필수 약관 동의를 유지한다. 체험 뒤로 약관을 옮기지 않는다.
3. 첫 친구를 만나고 실제 홈에 도착한다. 준비 완료·빈 기록·서버 활성화·필수 동의·미완료 조건에서 튜토리얼 초대가 자동으로 열린다.
4. 기존 RecordFlow에서 사진 → 가게 → 빵 태그 → 평가 → 날짜·메모를 경험한다.
5. 쌓을 빵을 고르면 전용 API로 저장한다. 서버 성공 전에는 완료·보상을 표시하지 않는다.
6. 빵탑에 쌓이는 연출을 보고 실제 홈에서 기록 1개와 빵탑 1개를 확인한다. 중간 빵카드는 없다.
7. 홈으로 돌아온 뒤 알림 허용 권유를 연결한다. 거절해도 기록과 보상은 유지한다.

### 준비된 재료

- 사진: 소금빵과 시작 캐릭터 빵댕이(dog)가 함께 있는 사진 1장. 앨범 권한·업로드 불필요.
- 가게: 선택 단계에서 빵댕이 빵집을 직접 선택한다. storeId/regionKey/menuId는 null이며 가짜 Store 행을 만들지 않는다.
- 태그: 사진을 터치하면 소금빵 이름표가 붙는다.
- 평가: 기존 평가 UI를 사용하며 선택하지 않아도 진행할 수 있다.
- 메모: 예시 문구를 한 번에 입력하거나 직접 수정·생략할 수 있다.
- 쌓을 빵: croissant / melonpan / soboro / bagel / anpan 중 선택.
- 템플릿: bbangdaengi-v1. 사진은 FE 번들과 BE classpath 정적 파일에 동일하게 포함한다.
- 이미지 생성 도구로 준비한 자산: “소금빵 실사와 빵댕이 캐릭터가 함께 있는 정사각 사진, 글자 없음”. 파일은 FE assets/onboarding/bbangdaengi-v1.png, BE static/onboarding/bbangdaengi-v1.png.

일반 기록의 사진 필수와 게스트 쓰기 제한은 그대로 유지한다. 튜토리얼만 서버가 정한 재료로 저장한다.

### 저장·수정·삭제

| 항목 | 정책 |
| --- | --- |
| 기록 | NORMAL/TUTORIAL 구분, 튜토리얼은 실제 비공개 기록 1개 |
| 수정 | 메모·평가·쌓을 빵만 전용 PATCH에서 허용 |
| 고정 | 사진·가게·날짜·유형, 일반 기록으로 전환 불가 |
| 삭제 | 소유자가 기존 삭제 API 사용 가능. 현재 기록과 빵탑 층 제거 |
| 삭제 후 | 완료 이력 유지, 재요청해도 새 기록·보상 없음 |
| 공용 사진 | 튜토리얼 삭제에서 S3 삭제 및 공용 자산 삭제를 수행하지 않음 |
| 세계관 | 활성 기록 수에는 포함, 기존 최고 도달 높이는 비감소 정책 유지 |

회원 잠금과 활성 튜토리얼 부분 고유 인덱스, memberId 기준 완료 이력으로 중복 저장을 막는다. 생성·완료 이력·성장 갱신은 한 트랜잭션이다.

### API 계약

모든 튜토리얼 API는 게스트 또는 회원 JWT가 필요하다. 인증 없는 공개 쓰기는 없다.

| API | 역할 |
| --- | --- |
| GET /bread-records/tutorial | enabled, templateCode, photoPath, storeName, breadName, towerBreads, completed, recordId, recordDeleted |
| POST /bread-records/tutorial | templateCode, eatenAt, memo, towerBread, 태그 위치·스타일, 선택 평가. 첫 완료 201, 재요청 200 |
| PATCH /bread-records/tutorial/{recordId} | 소유자 메모·평가·쌓을 빵 수정 |
| 기존 기록 조회·삭제 | recordType 포함 조회 및 소유자 삭제 |

서버는 사진 key·가게·빵 이름·비공개 여부를 고정하고 입력 좌표와 빵 종류를 검증한다. 필수 약관 3종과 제재·계정 활성 상태도 서버에서 검증한다. 기능 flag 기본값은 false이며 비활성화 뒤에도 기존 완료 응답과 기록 편집·삭제는 유지한다.

### recordType 타입과 이력 호환 정책

- 엔티티·기록 응답·월간 원천 스냅샷에서 동일한 `RecordType` enum을 사용한다.
- JSON 값은 기존 문자열 `NORMAL`/`TUTORIAL` 그대로이며 DB `VARCHAR + CHECK`는 변경하지 않는다.
- 과거 스냅샷의 필드 누락·null은 NORMAL로 정규화한다. 알 수 없는 문자열·숫자는 기존 SOURCE_HISTORY_UNAVAILABLE 오류로 집계를 중단한다.
- 원천 조회 전용 mapper에서 미지의 enum을 null로 바꾸는 옵션을 끄고 숫자 enum 변환도 차단한다. 전역 mapper 설정은 변경하지 않는다.
- 월간 집계는 TUTORIAL이 아닌 값 전체가 아니라 NORMAL만 허용한다. JSON 호환 및 과거/무효 이력 회귀 테스트로 검증한다.

### 게스트 승격과 이관

- 신규 소셜 가입: 동일 memberId 승격으로 기록과 완료 이력 유지.
- 기존 계정 로그인: 두 회원을 ID 순서로 잠근 뒤 대상 계정 완료 이력을 우선한다.
- 대상 미완료: 기록과 이력을 함께 옮긴다.
- 대상 완료·삭제 이력 존재: 게스트 중복 기록을 비활성화하고 대상 완료 이력을 유지한다.
- 닫히거나 이미 승격한 게스트를 다시 이관하지 않는다.
- 게스트 계정당·최종 회원 계정당 1회 보장이다. 재설치로 신원이 사라지는 경우까지 기기당 영구 1회라고 약속하지 않는다.

### 집계 경계

| 소비처 | 튜토리얼 처리 |
| --- | --- |
| 내 기록 목록·홈 빵탑·세계관 성장 | 포함 |
| 실제 가게 방문·지역·먹은 빵 통계 | 제외 |
| 월간 보고서 원천과 비교·연속일 | 제외, 과거 payload의 타입 누락은 NORMAL 호환 |
| 메뉴·가게 기반 순위·취향 | 가짜 menuId/storeId를 만들지 않음 |
| 광고 기록 전환·첫 일반 기록 이벤트 | NORMAL만 인정 |
| 신규 전체 D1/D7 코호트 | 튜토리얼 사용자를 분모에서 빼지 않음 |

사진·메모 원문을 분석 이벤트에 보내지 않는다. 기존 RecordFlow 단계 이벤트는 tutorial_ 접두어와 record_type으로 분리하고 별도 onboarding_tutorial_started/completed/save_failed를 남긴다.

### 알림 범위

성장 미션이나 편지를 새로 만들지 않는다. 이번 범위는 실제 저장·보상 확인 후 기존 권한 권유 연결이다. **D1~D7 꿀팁 콘텐츠·예약 발송은 미구현**이다. 권유 문구에서도 꿀팁은 준비 중임을 알리고 현재 제공하는 알림만 설명한다. 개발 preview는 저장과 권한 요청을 하지 않는다.

### 자동 검증 범위

BE 전체 테스트 2,176개 중 실패 0·오류 0·스킵 1. PostgreSQL 테스트는 일반 실행에서 제외되는 lab 태그로, localhost:5432 테스트 DB의 UUID 스키마에만 데이터를 만들고 정리한다. 공개/가게 연결 금지, 활성 기록 중복, 삭제된 완료 이력의 병합, 월간 보고서 제외를 검증한다. 이 검증을 실제 OAuth 또는 앱 전체 통합 테스트로 표현하지 않는다.

### 배포·롤백

1. BE main 기반 PR과 FE PR을 함께 검토한다. 서버·DB 배포와 앱 배포는 PR 생성과 별개다.
2. 서버 migration/API가 준비된 개발 환경에서 먼저 켠다. cd-staging에 tutorial.enabled=true를 추가하되 실제 배포는 아직 하지 않았다.
3. 현재 개발 서버가 계약을 지원하지 않으면 초대는 숨긴다. 일반 생성 API로 우회하거나 가짜 성공을 표시하지 않는다.
4. 운영 flag는 기본 false로 유지한다. 스키마·정적 사진·앱 호환 및 QA 후 활성화한다.
5. 되돌릴 때 신규 생성 flag만 끄고 저장된 기록·완료 이력은 보존한다.
6. main과 dev는 분기 이력이 다르다. main 기반 결과물을 공유 dev에 덮어씌우지 않고 개발 배포 시 dev 기준 통합을 별도 확인한다.

현재 로컬 앱 설정은 개발 API(bbang-ggut.site)다. .env.local은 PR에 포함하지 않는다. 운영 DB 변경·서버 배포·푸시 발송은 이 검증에서 수행하지 않았다.

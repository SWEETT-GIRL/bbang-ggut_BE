# 응답 변경 에이전트 후속 구현·검증 — 2026-10-14

동시 수집/메뉴 삭제 승인, PostgreSQL 사건 전달·중단 복구, 가격 계약의 반례,
45,000개 파일 보관 비용을 보완했다. Sonnet을 통한 과거 사건 재현과 현재 서버의
100곳 수집을 따로 실행했다. 생성한 과거 파서 패치의 운영 적용과 운영 DB 쓰기는 0건이다.
이번 spec/plan은 사용자 요청대로 로컬에만 보관한다.

## 선택과 한계

- 원본 수신/재평가의 커밋과 메뉴 삭제 승인은 가게별 PostgreSQL transaction advisory
  try-lock을 공유한다. 승인은 근거 검사부터 claim, serving DML, 결과 확정까지 별도
  연결을 유지한다. JPA 풀을 잠금 연결로 채우는 교착을 피하려는 선택이다. 경합 시
  즉시 실패하며 연결 상실을 알면 쓰기 전에 중단한다. 모든 작성 프로세스가 새 규약을
  사용해야 하고, 별도 DataOps/Serving DB 사이의 분산 원자성을 보장하지는 않는다.
- `response_agent_run`에 임대, fencing epoch, 비용 예약, 메시지/도구 cursor와 실행 상태를
  함께 기록한다. LangGraph 별도 PostgreSQL checkpointer를 추가하지 않고 업무 원장과
  재개 경계를 함께 검사했다. 모델 응답/도구 완료 경계는 이어 실행하지만, 응답 유실이나
  도구 실행 중 중단은 자동 재시도하지 않는다. 수정된 입력·실행 코드·예산을 몰래 적용해
  재개하지 않으며, 중간 파일 누락도 보류한다. 완전한 전원 장애 복구를 검증한 것은 아니다.
- capture/incident는 SELECT, 실행 원장만 SELECT/INSERT/UPDATE 권한인 worker를 검증했다.
  현재 catalog는 사건·파서·계약·원본 digest와 사전 확정된 익명화 자료/기대값을 연결한다.
  미등록 사건의 의미나 정답을 자동 확정하지 않는다. 처음 보는 구조 전반에 대한 자동
  수리나 현재 서버의 무인 agent 운영 완료를 주장하지 않는다.
- 중단 후 검수 파일은 DB 체크포인트를 기준으로 `dispatch-epoch-N`에 재생성한다.
  실행 중 작업 디렉터리의 `report.json`보다 최종 반환된 epoch별 보고서가 기준이다.
  대기 중인 사건도 현재 명시한 더 낮은 최초 실행 비용 상한을 적용한다.
- spool 사용량은 배치 잠금 안에서 한 번 조회하고 원자적 파일 교체의 크기 차이를 반영한다.
  실패하면 캐시를 버린다. 단독 작성도 같은 잠금을 사용하며 ACK 후 원본을 삭제하지 않는다.

## Sonnet 가격 계약 v2 실호출

최초 실행의 [사후 검토 보류](./agent-historical-replay-20261014.md)는 그대로 유지한다.

실제 저장 원본을 임시 PostgreSQL에 과거 재현 사건으로 넣고, 제한된 worker 권한으로

원본은 digest 연결에만 사용하고 모델에는 정제된 부분만 보냈다. Opus 추가 호출, 사람의

최초 v1의 $0.166162와 이번 수치는 계약/평가 자료와 실행 경로가 달라 성능 절감률의

수동 작업 기준선도 없어 사람 작업 시간 절감률을 만들지 않는다.

## 45,000개 파일 저장 비용

합성 파일 45,000개, 총 14,478,890 bytes에서 동일한 64회 ACK 저장을 비교했다.
실제 atomic replace와 파일/디렉터리 fsync를 포함해 **9.278976초 → 0.120734초**였고,
전체 디렉터리 조회는 **64회 → 1회**였다. 원본 파일 45,000개와 선택한 raw/digest를 보존했다.
실제 45,000곳 네트워크 수집 시간이나 서버 전체 처리량의 개선율로 해석하지 않는다.

근거: `artifacts/response-agent/spool-scale-20261014/benchmark.json`.
보존·삭제 기간이나 무제한 디스크 사용을 결정한 변경은 아니다. 기존 용량 상한은 유지한다.

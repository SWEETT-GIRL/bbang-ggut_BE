## 문제와 선택

기존 합성 probe는 도구 왕복만 확인했다. 실제 수집의 호출 0회를 에이전트
분류 성공으로 해석할 수 없었고, 원본→패치→독립 검증 경로도 없었다.
이번에는 같은 가게의 저장 원본 두 개와 과거 파서를 고정하여 좁은 경로를
실행했다. 사람이 작성한 현재 수정 코드는 모델에게 제공하지 않았다.

LangGraph가 모델·도구 왕복을 구성하고 실행기가 근거·패치·검증 상태를
검사한다. 여섯 도구 중 선택은 `tool_choice=auto`의 Sonnet이 했다. 현재
서비스와 DB를 변경하지 않는 평가를 위해 별도 SQLite inbox를 사용했다.
운영 PostgreSQL 사건 소비자와 영속 graph checkpoint는 아직 구현하지 않았다.
중단 후 자동 재호출 대신 미완료 상태와 비용 예약액을 남기는 선택이다.

## 후속 검토에서 발견한 실패

고정 평가 통과 후 독립 코드 검토(Codex)가 새 가격 함수의 추가 분기를 확인했다.
`PlaceMenuItem.price`가 문자열·숫자이면 `displayText` 검증 없이 그대로 반환한다.
이는 ‘displayText가 없으면 null, 의미를 추정하지 않음’ 계약과 일치하지 않는다.

| `"시가"` | null | `"시가"` |

추가 세 사례에서 모두 재현됐다. 같은 형태의 기존 `Menu` 값은 기존 계약대로
보존됐다. 이 세 사례는 **결과를 본 뒤 만든 검토 반례**이며 최초 고정 평가에
소급 합산하지 않았다. 원래 fixture와 후보 패치도 수정하지 않았다.

따라서 최초 graph 결과는 보존하고 별도 검토 기록으로 inbox를 `HELD`로 전환했다.
테스트 통과를 승인으로 취급하지 않았고, 보류 사건을 다시 전달해도 API 호출은

>
> **전수 실측 결과 (08-02~07, 3세션 + 쿨다운 자동 재개):**
> AUTO **9,313 (65.2%)** — 거리 중앙값 3m·90p 14m·전화일치 2,212 / REVIEW 1,601 (11.2%) /
> NOT_FOUND 3,376 (23.6%, 그중 **후보 0건 2,502 = 폐업·네이버 부재 후보군**).

## 1. 문제 정의

- 미매칭 14,500곳은 네이버 플레이스 페이지가 없어 **크롤 파이프라인에 태울 수 없다.** 재크롤 스케줄 문제가 아니라 매칭 문제다.
- 이 가게들의 이름·주소·좌표는 **카카오 기준**(KAKAO_IMPORTED)이다. 네이버 상호와 표기가 다를 수 있어 **이름 매칭은 신뢰할 수 없다** — 이미 매칭된 가게조차 정규화 후 12%가 이름 불일치(리서치 2.3), 브랜딩 변형과 오매칭을 문자열로 구분 불가가 실측 결론.
- 과거 수동 enrich(어드민 UI)로 30,980까지 왔고, 남은 14,500은 자동화 + 검수 조합이 맞는 규모다.

## 2. 원칙 — 비용 비대칭

| 결과 | 비용 |
|---|---|
| 매칭 실패(미발견) | **0** — 현상 유지, 다음 기회에 재시도 가능 |
| 오매칭 | **크다** — 엉뚱한 가게의 메뉴·영업시간·폐업 신호가 우리 가게에 붙는다. 이후 모든 재동기화가 오염을 강화 |

→ **임계는 보수적으로.** 애매하면 자동 확정하지 않고 검수로 보낸다. 미발견율이 높은 것은 실패가 아니다.

## 3. 매칭 신호 체계 (강한 순)

미매칭 가게도 카카오 임포트 자산(좌표 `location`·주소·일부 전화번호)을 갖고 있다.

| 순위 | 신호 | 근거·특성 |
|---|---|---|
| 1 | **전화번호 일치** | 있으면 사실상 확정. 단 060/안심번호 제외 |
| 2 | **좌표 거리** | 카카오·네이버 좌표는 같은 가게면 보통 수십 m 이내. 가장 보편적인 결정 신호 |
| 3 | **도로명주소 정규화 일치** | 좌표의 교차 검증 (건물 단위) |
| 4 | 이름 유사도 (정규화 후) | **보조 신호로만** — 공백·기호·지점명 제거 후 부분 일치 |

## 4. 검색 전략 — 후보 수집 (이름이 달라도 건지도록 다층)

| 층 | 쿼리 | 커버 |
|---|---|---|
| 1차 | `정규화 이름 + 동네` (예: "형제꿀빵 조치원") | 표기 유사 가게 |
| 2차 | 지점명·수식어 제거한 **코어 이름** + 지역 | 브랜딩 변형 |
| 3차 | **좌표 반경 역방향 스윕** — 가게 좌표 주변 "베이커리/빵집" 검색 → 후보 목록을 좌표 최근접 대조 | **이름이 완전히 달라도** 좌표로 포착 |

> ✅ **검색 경로 실측 (2026-08-02)**: `allSearch` 직접 requests 호출은 **캡차 토큰 부재로 빈 결과**를 주는 소프트 차단(`pageId: ncaptcha-all-search-no-result`) — 상세 페이지와 달리 검색은 requests 불가. **Playwright(브라우저) 경유는 통과** — 워커(`scripts/match_worker.py`)는 브라우저 기반으로 map.naver.com 검색 후 allSearch 응답을 가로챈다. 처리 속도 ~5초/가게.

## 5. 판정 — 3-way

| 판정 | 규칙 초안 (파일럿 후 확정) | 처리 |
|---|---|---|
| **자동 확정** | 전화 일치 · 또는 (거리 <50m ∧ 주소 건물 일치 ∧ 이름 유사) | naver_place_id 반영 → sync_state 생성(T1) → 크롤 궤도 진입, **첫 크롤이 곧 백필** |
| **검수 보류** | 후보는 있으나 신호가 약함 (예: 거리 <150m ∧ 이름 유사, 주소 불일치) | 승인함에 수납 — 근거(후보 place_id·거리·이름 대조) 첨부, 어드민 승인 시 반영 |
| **미발견** | 3층 검색 모두 유효 후보 없음 | 상태만 기록, 종료. 폐업 가능성 신호로도 쓰되 단정 금지(리서치 2.3 — 단일 신호 폐업 판정 불가) |

- `naver_place_id` 채움은 **운영 DML** 이다 — 다른 반영과 동일하게 `ServingWriter` 단일 통로 + `apply_log` 선기록 원칙 적용. 즉 **본격 가동은 2단계(쓰기 인프라) 이후**가 자연스럽다.
- 검수 보류는 `change_proposal(target='store.naver_place_id')` 패턴을 그대로 재사용한다.

## 6. 데이터 모델 초안 — 상태가 곧 워크리스트 (큐 없음 원칙 유지)

```sql
CREATE TABLE store_match_candidate (
    id                 BIGSERIAL PRIMARY KEY,
    store_id           BIGINT      NOT NULL UNIQUE,   -- 운영 store.id (논리 참조)
    status             VARCHAR(20) NOT NULL DEFAULT 'WAITING_SEARCH',
                       -- WAITING_SEARCH | AUTO_MATCHED | NEEDS_REVIEW | NOT_FOUND | REJECTED
    matched_place_id   VARCHAR(50),                   -- 확정/후보 place_id
    distance_meters    INT,                           -- 좌표 거리 (근거)
    name_similarity    NUMERIC(4,3),                  -- 이름 유사도 (근거)
    phone_matched      BOOLEAN,
    search_attempts    INT NOT NULL DEFAULT 0,
    evidence           JSONB,                         -- 검색 응답 요약 (검수 화면 근거)
    created_at         TIMESTAMP NOT NULL DEFAULT now(),
    updated_at         TIMESTAMP DEFAULT now()
);
CREATE INDEX idx_match_candidate_status ON store_match_candidate (status);
```

- 워커 매칭 모드가 `WAITING_SEARCH` 를 폴링 — 4단계 `new_store_candidate(WAITING_NAVER)` 와 **동일 메커니즘**이므로 candidate 인프라(워커 매칭 모드·검색 클라이언트)를 공유한다.
- 신규 가게(공공데이터)와 기존 미매칭의 차이는 "매칭 후 store INSERT냐, 기존 store UPDATE냐"뿐이다.

## 7. 파일럿 — 트랙 구현 전 선행 게이트

| 항목 | 내용 |
|---|---|
| 표본 | 미매칭 100곳 (md5 결정적 추출 — 관찰 표본과 동일 방식) |
| 측정 1 | `allSearch` 검색 경로가 requests 로 성공하는가 (차단·캡차 여부, 지속 요청률) |
| 측정 2 | 자동 확정률 / 검수 보류율 / 미발견율 |
| 측정 3 | 자동 확정분 표본 눈검사 — **오매칭 0건이어야 임계 통과** (오매칭 발견 시 임계 상향 후 재측정) |
| 게이트 | 검색 경로 안정 + 자동 확정 오매칭 0 → 트랙 구현 착수. 검색 경로 차단 시 트랙 보류(수동 enrich 지속) |

## 8. 도입 시점

| 시점 | 내용 |
|---|---|
| 1단계 관찰 완주 후 | 파일럿 100곳 (읽기·검색만 — 운영 쓰기 불요) |
| 2단계(쓰기 인프라) 이후 | 자동 확정분 운영 반영 가동 |
| 4단계(candidate) 구현 시 | 검색 클라이언트·워커 매칭 모드 공유로 본격 가동 |

## 9. 리스크·보류

| 항목 | 상태 |
|---|---|
| 검색 경로(`allSearch`) requests 가능 여부 | ✅ 실측 완료 (08-02) — requests 불가(캡차), **Playwright 경유 확정** |
| 검색 요청 rate limit (브라우저 경유 지속 요청) | ⚪ 야간 대량 실행으로 관측 중 — 캡차 감지 시 exit 3 |
| 미매칭 집단의 폐업 비율 | ⚪ 미상 — 미발견율에 섞여 나옴. 폐업 판정은 이 트랙 범위 밖 (공공데이터 파일럿 몫) |
| 임계값 수치 (50m·유사도 등) | 초안일 뿐 — 파일럿 실측으로 확정 |
| 카카오 좌표 품질 (오프셋·오등록) | ⚪ 자동 확정 눈검사에서 함께 관찰 |

## 남은 예외와 처리 원칙

### 1. 경계 파일 내부의 중첩

복수 매칭은 화성 34, 대구 9, 성남 1, 창원 1곳이다. 45곳 모두 두 도형 내부에 있다(ST_Contains). 단순 공유 경계선 문제나 ST_Covers 선택 때문이 아니다. 해당 경계는 원본에서도 유효해 복구 과정이 만든 중첩이 아니다.

- 화성 병점구 능동 `4159510300`과 동탄구 능동 `4159710100`의 도형은 ST_Equals=true이며 각각 약 2.708km²다. 가게 34곳 중 적격 29곳. 도시 소속은 화성시로 같으므로 도시 후보에 포함할 수 있지만 구·동 코드는 보류해야 한다.
- 대구는 서로 다른 구의 경계 중첩으로 전체 9곳, 적격 5곳이다. 지역 범위까지 복수라 선택 근거를 추가 검수해야 한다.
- 성남과 창원의 각 1곳은 같은 도시 안 중첩이며 추천 비적격이다.

적격에서 도시/앱 지역까지 확정 가능한 가게는 37,796/37,812(99.9577%)다. 남은 16곳은 대구의 복수 앱 지역 5곳과 미매칭 11곳이다. 이 숫자를 근거로 미확정 가게를 서비스에서 영구 제외하지 않는다.

### 2. 미매칭 16곳

인천 6, 경기 3, 경북 3, 부산 2, 서울 1, 경남 1곳이다. 0.1도 이내 경계들을 검색해 측정한 최소 거리는 약 0.18~669m. 15곳은 100m 이내, 창원 1곳은 약 669m다. 경계 틈·좌표 오차·경계 변경 등을 아직 구분하지 못했다.

가까운 폴리곤으로 자동 편입하면 다른 구·동으로 잘못 지정할 수 있다. 최신 공식 변동분과 좌표의 법정코드 근거를 추가 대조한다. 검색 반경 밖까지 전수 최근접을 계산한 것은 아니다.

### 3. 기존 지역 문자열 차이

단일 법정코드로 매칭된 전체 53,040곳 가운데 다음과 같이 분류했다.

- 일치 52,684곳. 법정동의 끝 N가 접기와 시도 약칭, 기준표 공백을 정규화했다.
- 읍면동 차이 343곳(적격 69곳). 행정동/법정동 혼용, 좌표·경계 차이 등의 검수 후보이며 오류 확정 수가 아니다.
- 시·구 표시 차이 12곳: 모두 인천의 과거 표시(중구/서구 등)와 기준표의 현 코드 경로 차이. 모두 추천 비적격이다. 실제 개편 이력은 별도 확인한다.
- 3번째 필드에 구가 보존된 1곳: 창원 성산구. 4단계 주소 표현이며 잘못된 주소로 단정하지 않는다.

세종은 전체 370곳, 적격 260곳 모두 단일 매칭이고 기존 투영과 일치한다. 성남의 시·구·동, 세종의 단계 생략을 같은 필드 위치로 억지 보정하지 않았다.

### 4. 무효 306행과 이름 차이

유효 경계의 서로 다른 코드 5,067개와 기준표의 읍면동 5,067개가 정확히 대응한다. 기준표 코드의 경계 누락 및 기준표 밖 유효 경계 코드는 0개다. 따라서 무효 306행을 ‘306개 읍면동 누락’으로 해석하면 안 된다.

무효 행 이름 칸의 19자리 값 접두사를 진단 목적으로 대조하면 인제 기린면 303행, 남원 대산면 2행, 합천 대병면 1행이다. 도형 안에 있는 로컬 가게는 0곳이다. 이 접두사를 정식 코드로 채택하거나 폴리곤을 병합하지 않았다. 신규 가게에 대한 영향까지 없다는 뜻은 아니다.

유효 코드 중 경계 이름과 기준표 이름 차이는 5개다(청주 북문로/남문로의 ‘가동’ 표기, 창원 ‘장군동5’). 이름 기반 매칭 대신 기준표 코드를 사용했고, 원문 차이는 JSON에 보존했다.

## 반영 설계

1. 공식 경계와 법정 코드 기준표를 버전으로 묶는다. 기존 3개 표시 필드는 보존한다.
2. 가게 좌표별 법정코드 상태와 앱 지역 상태를 별도로 저장한다. 단일 코드, 동일 도시의 복수 코드, 복수 도시, 미매칭을 구분한다.
3. 같은 도시의 복수 코드는 도시 후보 확보에 이용하되 하위 구·동을 임의 확정하지 않는다. 미매칭·복수 도시는 재조회/검수 근거를 남긴다.
4. 신규 가게·좌표 변경에 같은 판정 경로를 적용하고, 경계 버전 변경 시 재판정한다. 오래된 좌표의 판정을 재사용하지 않는다.
5. 전국 데이터 준비 상태를 확인한 후 추천 후보 조회와 기존 API 계약에 연결한다. 현재 단계는 로컬 진단이며 테이블 값 일괄 변경·배포가 아니다.

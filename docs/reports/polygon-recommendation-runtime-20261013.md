# 폴리곤 추천 API 연결 및 로컬 검증

2026-10-13 · 브랜치 `feat/742-polygon-course-lab` · base `a913ac3f`.

## 구현한 동작

기존 앱의 지역 선택 요청을 공식 법정동 집합에 연결했다. 최초 추천은 선택 영역 전체의 가게를 기존 취향 점수식으로 비교하고, 요청 수와 구간·총거리 제약을 만족하는 코스를 탐색한다. 도시 전체를 상위 15곳으로 먼저 자르지 않는다.

- 활성 59개 지역 행 / 48개 칩을 1,761개의 법정 읍면동 코드에 매핑했다. 전국 경계 자체는 5,067개이며 코드 기반 앱 영역은 262개다.
- 서울은 기존 6개 동 칩을 유지한다. 성수는 법정동 1가·2가를 합친다. 세종도 도담동/조치원읍의 선택 의미를 유지한다.
- 인천 중구는 개편 전 기준표의 52개 법정동명을 현행 기준표에 일대일 대응했다(제물포구44+영종구8). 제물포구 전체를 합쳐 옛 동구7개를 섞지 않는다. [인천시 개편 설명](https://www.incheon.go.kr/IC01070101). 기준표 해시는 적재 도구에 고정되어 있다.
- 같은 칩의 동네 행이 여러 개여도 가게 수와 신호는 한 번 센다. 후보와 같은 자격·현재 좌표 판정 조건을 사용한다.
- 최초 결과의 중심/반경을 저장한다. 기본 반경 1,200m보다 경로가 넓으면 경로 전체가 포함되도록 늘린다. RETRY는 같은 경계 버전·바인딩·범위·거리 정책을 유지한다. exactArea는 기존 동네 중심과 반경을 고정한다.
- 같은 시트 재진입은 가게 자격·현재 좌표·현재 일차의 마지막 가게를 재검증하고 유효한 노출 가게를 유지 우선순위로 둔다. 새 세션·재추천은 이전 노출을 제외한다. 다음 동네는 후보가 있고 현재 코스에서 연결 가능한 곳만 제안한다.
- `recommendation.result` 내부 정보만 확장했다. 공개 응답 필드·Gemini 이유 생성 API·담기 API를 유지한다. Gemini 문장 갱신 후 scope 보존을 서비스 테스트로 검증했다.

## 검증 결과

`PolygonRecommendationRuntimeLabTest`는 Docker 로컬 복제본과 실제 PostGIS 후보 SQL을 사용했다. 독립적인 ST_Covers 조회와 후보 ID 전체를 대조했다. 변형 검증은 임시 스키마의 복제 행만 수정하고 롤백했다.

| 검증 | 결과 |
|---|---|
| 활성 지역 매핑 | 59/59, 48칩 |
| 칩 숫자 vs 후보 집합 vs 직접 폴리곤 조회 | 59곳 모두 일치 |
| 취향 없는 최초 요청 1·4·6곳 | 177/177 요청 수 충족, 거리 제한 준수 |
| 실제 프로필 18개×성남/수원/고양×최초/재추천2회 | 162/162에서 4곳 충족, 기록·노출 제외 및 총거리 준수 |
| 좌표 변경·비활성·빵집 점수 미달·명시 제외 | 후보에서 제외 |
| course_area의 지역 의미 변경 | 기존 binding 사용 거부 |
| 지역 경계 SQL 재적재 | 도형5,067·바인딩59, 도형/계층/연결 차이0, DDL까지 롤백 |

실제 프로필 검증은 축 없음/축만 있음/종류 선호 있음 각 6개를 회원 ID순으로 선택했다. 이전 비교 실험의 방문기록 많은 순 표본과 다르다. 개인별 입력·ID·추천 경로는 보고서에 포함하지 않는다. RETRY 범위와 제외 이력은 모의이며 실제 HTTP나 운영 코스 저장을 재현한 E2E가 아니다. 서비스 단위 테스트에서 별도로 소유·일차·세션·좌표 변경·다회차 저장·Gemini 갱신을 검증한다.

로컬 단일 실행에서 도시 전체 후보 SQL은 중앙값31ms/최대163ms, 후보 조회 후 1·4·6곳 세 탐색의 합은 중앙값10ms/최대89ms였다. 칩 쿼리·재조회·저장·HTTP·Gemini와 동시 부하는 포함하지 않으므로 운영 응답 지연이나 SLO 근거로 쓰지 않는다. 후보 최대는 수원1,015곳이었다.

최종 `./gradlew build -x installGitHooks` 성공. 기본 테스트 2,724건, 실패·오류 0, 건너뜀 1건이며 Spotless·Checkstyle도 통과했다. 별도 PostGIS 테스트 10건(지역 판정7·런타임3)을 통과했다. 상세 비개인 집계는 [JSON](polygon-recommendation-runtime-20261013.json)이다.

## 재현

```bash
POLYGON_REGION_LOAD=<로컬 runtime-load.json> \
POLYGON_RUNTIME_REPORT=<Git 밖 결과 경로> \
./gradlew test -PlabTests \
  --tests '*PolygonRecommendationRuntimeLabTest' \
  --tests '*StoreRegionResolutionRepositoryLabTest' -x installGitHooks

./gradlew spotlessApply build -x installGitHooks
```

`load_region_boundaries.py`로 로컬 판정 버전을 적재한 뒤 `load_course_area_bindings.py`로 공식 코드 연결을 적재한다. 큰 SHP/릴리스 SQL은 Git 밖에 두며 [배포·복귀 절차](../planning/polygon-recommendation-release-742.md)에 재적재 순서를 기록했다.

## 해석 범위와 배포

경계2026-09-09·코드표2026-09-26·로컬 가게 최신2026-09-19 기준이다. 후보 확장은 더 많은 가게를 비교할 기회를 만들지만 사용자 만족도 상승이나 모든 입력의 취향 점수 상승을 보장하지 않는다. 현재 탐색은 다중 출발점의 두 탐욕 경로를 비교하며 최적해 보장은 없다. 기존 랩 D_HYBRID의 점수 개선 수치를 이번 런타임 구현의 운영 효과로 옮기지 않는다.

거리는 직선거리다. 물길·고속도로·섬 등 도로 단절을 판단하거나 도보 경로를 계산하지 않는다. 기존 앱의 ‘도보’ 표기와는 별도로 staging에서 동선을 검수해야 한다. 기본 총거리 설정은 4곳1,500m/6곳2,500m이며 코스 끝→첫 추천 거리도 포함한다. 응답 totalDistanceM는 기존 계약대로 추천 가게 사이 합이다.

전국 적격 가게 중 미매칭11곳·복수 앱 지역5곳은 자동 보정하지 않는다. 선택 영역 밖 코드와 함께 매칭되는 가게는 제외한다. 표시 불일치69곳은 오류 확정 수가 아니며 원래 region 필드는 유지한다.

기능 플래그 기본값은 false다. 구현·로컬 검증을 완료한 PR이며 운영 자료 적재/활성화는 수행하지 않았다. #742는 배포 검수까지 추적할 수 있도록 자동 종료하지 않는다.

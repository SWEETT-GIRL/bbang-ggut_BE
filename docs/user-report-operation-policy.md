# 사용자 신고 운영 정책

작성일: 2026-06-04

이 문서는 빵긋 서비스의 리뷰, 프로필, 향후 댓글 신고를 처리하기 위한 내부 운영 기준이다.
법률 자문 문서가 아니며, 실제 약관/개인정보 처리방침/스토어 심사 문구는 별도 검토가 필요하다.

## 참고한 외부 기준

- Apple App Store Review Guidelines 1.2는 UGC 앱에 부적절한 콘텐츠 필터링, 신고 장치,
  신속한 대응, 악성 사용자 차단, 연락 수단을 요구한다.
  <https://developer.apple.com/app-store/review/guidelines/>
- Google Play UGC 정책은 약관 동의, 금지 콘텐츠 정의, 신고/차단 기능, 적절한 조치를 요구한다.
  <https://support.google.com/googleplay/android-developer/answer/9876937>
- YouTube는 90일 기준의 누적 strike와 단계적 기능 제한을 사용하며, 반복 위반 또는 중대 위반은
  계정 종료까지 이어질 수 있다.
  <https://support.google.com/youtube/answer/2802032>
- TikTok은 자동/수동 검수, 신고 기반 추가 검수, 조치 사유 안내, 이의제기 상태 확인을 운영 원칙으로 둔다.
  <https://www.tiktok.com/community-guidelines/en/enforcement/>

## 운영 원칙

- 안전 우선: 개인정보 노출, 협박, 혐오, 성적 콘텐츠, 아동/청소년 위해 가능성은 일반 신고보다 우선 처리한다.
- 비례성: 위반 정도와 반복성을 함께 보고 경고, 숨김, 삭제, 제한, 정지 순서로 조치한다.
- 최소 노출: 신고자는 피신고자에게 공개하지 않는다. 피신고자에게도 신고자 정보를 제공하지 않는다.
- 추적 가능성: 모든 신고, 검수 결과, 관리자 조치, 이의제기는 변경 이력으로 남긴다.
- 재검토 가능성: 콘텐츠 삭제, 프로필 초기화, 계정 제한 이상의 조치는 사용자가 이의제기할 수 있어야 한다.
- 악용 방지: 허위 신고를 반복하는 회원은 신고 기능 제한 또는 계정 제재 대상이 된다.

## 신고 대상

현재 API에서 허용하는 대상:

- REVIEW: 리뷰 본문, 리뷰 이미지, 별점/평가 표현을 포함한다.
- MEMBER_PROFILE: 닉네임, 프로필 이미지, 자기소개 등 공개 프로필 요소를 포함한다.

추가 예정 대상:

- REVIEW_COMMENT: 리뷰 댓글 기능이 생기면 댓글 신고를 분리한다.
- STORE_CONTENT: 사용자 작성 매장 설명, 사진 캡션 등 UGC 범위가 생기면 분리한다.

## 신고 사유

API enum과 운영 라벨은 다음처럼 매핑한다.

| reasonType | 사용자 라벨 | 대표 사례 |
| --- | --- | --- |
| SPAM | 광고/도배 | 반복 홍보, 외부 링크 유도, 의미 없는 반복 문구 |
| ABUSE | 욕설/비방 | 개인 공격, 조롱, 모욕, 집단 따돌림 유도 |
| HATE | 혐오 표현 | 인종, 성별, 장애, 국적, 종교, 성적 지향 등 보호 특성 공격 |
| PRIVACY | 개인정보 노출 | 전화번호, 주소, 실명, 계정 정보, 사적 사진 노출 |
| SEXUAL | 음란/선정 | 성적 표현, 원치 않는 성적 대상화, 음란 이미지 |
| ETC | 기타 | 위 분류에 맞지 않지만 운영 검토가 필요한 내용 |

프론트는 `ETC` 선택 시 상세 사유 입력을 권장한다. `reasonDetail`은 선택값이지만 최대 500자로 제한한다.

## 검수 등급

| 등급 | 의미 | 기본 처리 시간 | 예시 | 기본 조치 |
| --- | --- | --- | --- | --- |
| S0 | 위반 아님 | 5영업일 | 취향 차이, 정당한 비판 | REJECT |
| S1 | 경미한 위반 | 72시간 | 반복 이모지, 약한 비방, 맥락 없는 글 | 경고 또는 숨김 |
| S2 | 일반 위반 | 24시간 | 명백한 욕설, 광고, 허위 후기 패턴 | 콘텐츠 숨김/삭제 + 경고 |
| S3 | 중대 위반 | 4시간 | 개인정보 노출, 혐오, 성적 콘텐츠, 협박 | 즉시 숨김 + 계정 제한 검토 |
| S4 | 긴급 위반 | 즉시 | 아동 위해, 실제 위해 협박, 범죄 모의, 민감 개인정보 대량 노출 | 즉시 삭제/정지 + 별도 대응 |

S3 이상은 신고 접수 수와 무관하게 단일 신고만으로 선조치할 수 있다.

## 콘텐츠 조치

리뷰:

- 위반 아님: 신고 `REJECTED`, 리뷰 유지
- 경미한 위반: 리뷰 숨김 또는 수정 요청
- 일반 위반: 리뷰 숨김 후 삭제, 작성자 경고
- 중대 위반: 즉시 숨김/삭제, 작성자 기능 제한 검토

프로필:

- 위반 아님: 신고 `REJECTED`, 프로필 유지
- 경미한 위반: 닉네임/프로필 이미지 수정 요청
- 일반 위반: 닉네임 또는 프로필 이미지 강제 초기화
- 중대 위반: 강제 초기화 + 프로필 수정 제한 또는 계정 제한 검토

향후 댓글:

- 리뷰보다 더 빠르게 숨김 처리한다.
- 같은 스레드에서 반복 비방이 발생하면 댓글 작성 제한을 우선 적용한다.

## 계정 제재 단계

위반 이력은 최근 90일 기준으로 누적한다. 중대 위반은 누적 단계와 무관하게 상위 제재를 적용할 수 있다.

| 최근 90일 확정 위반 | 기본 제재 |
| --- | --- |
| 1회 | 경고 |
| 2회 | 3일 작성 제한 |
| 3회 | 7일 작성 제한 |
| 4회 | 30일 작성 제한 |
| 5회 이상 | 계정 정지 검토 |

즉시 강한 제재가 가능한 경우:

- 개인정보를 의도적으로 노출한 경우
- 특정 개인에게 실제 위해를 암시하거나 협박한 경우
- 혐오/성적 표현이 명백하고 반복 가능성이 높은 경우
- 계정이 광고, 도배, 악성 활동 전용으로 판단되는 경우
- 제재 회피를 위해 새 계정 사용이 의심되는 경우

## 자동 선조치 기준

자동 선조치는 최종 제재가 아니라 임시 안전 장치다.

- 같은 리뷰가 서로 다른 신고자 3명 이상에게 24시간 내 신고되면 임시 숨김 후보로 표시한다.
- `PRIVACY`, `HATE`, `SEXUAL` 신고가 2명 이상에게 접수되면 우선 검수 큐 상단으로 올린다.
- 동일 회원의 리뷰 3개 이상이 24시간 내 신고되면 회원 단위 검수 큐를 생성한다.
- 신규 계정이 10분 내 리뷰/댓글을 반복 작성하고 신고가 발생하면 작성 제한 후보로 표시한다.

초기 버전에서는 자동 숨김을 바로 켜지 않는다. 운영 데이터가 쌓일 때까지는 관리자 큐 우선순위만 조정한다.

## 관리자 처리 플로우

1. 신고 목록에서 `PENDING` 상태를 확인한다.
2. 신고 대상 원문, 작성자 이력, 신고 사유, 과거 90일 확정 위반 수를 확인한다.
3. 등급을 S0-S4로 판단한다.
4. 신고 상태를 `ACCEPTED` 또는 `REJECTED`로 처리한다.
5. 필요 시 콘텐츠 조치와 계정 제재를 별도 액션으로 실행한다.
6. 조치 대상자에게 사유와 이의제기 경로를 안내한다.
7. 신고자에게는 상세 제재 내용 없이 처리 완료 여부만 안내한다.

현재 구현된 관리자 API는 신고 상태 처리까지만 담당한다.

```http
GET /api/admin/reports?kind=USER_REPORT&status=PENDING&page=0&size=20
PATCH /api/admin/reports/{reportId}
```

```json
{
  "kind": "USER_REPORT",
  "action": "ACCEPT"
}
```

콘텐츠 삭제, 프로필 초기화, 계정 제한은 다음 단계에서 별도 moderation action API로 구현한다.

## 이의제기

이의제기 대상:

- 리뷰 삭제
- 프로필 강제 초기화
- 작성 제한
- 계정 정지

이의제기 기간:

- 조치 통지 후 30일
- 계정 정지는 90일

운영 원칙:

- 최초 처리자가 아닌 관리자가 재검토한다.
- 이의제기가 받아들여지면 콘텐츠 복구, 제한 해제, 위반 카운트 제거를 수행한다.
- 명백한 악성 콘텐츠나 법적 위험이 있는 콘텐츠는 복구하지 않는다.

## 허위 신고 및 신고 악용

다음 패턴은 신고 악용으로 본다.

- 같은 대상 또는 같은 작성자에게 반복적으로 근거 없는 신고를 제출하는 경우
- 경쟁 매장, 특정 회원, 특정 취향을 공격하기 위한 조직적 신고
- 신고 상세 사유에 욕설, 협박, 개인정보를 포함하는 경우
- 본인이 불리한 리뷰를 삭제시키기 위한 반복 신고

최근 90일 기준 허위 신고 조치:

| 허위 신고 확정 횟수 | 제재 |
| --- | --- |
| 3회 | 신고 기능 7일 제한 |
| 5회 | 신고 기능 30일 제한 |
| 10회 이상 | 계정 제한 검토 |

## 프론트 안내 문구

신고 화면:

```text
신고 사유를 선택해 주세요.
신고는 운영팀 검토 후 처리되며, 신고자 정보는 상대방에게 공개되지 않습니다.
허위 신고가 반복되면 서비스 이용이 제한될 수 있습니다.
```

신고 완료:

```text
신고가 접수되었습니다.
운영팀이 검토한 뒤 필요한 조치를 진행합니다.
```

이미 신고한 대상:

```text
이미 신고한 콘텐츠입니다.
검토가 완료될 때까지 기다려 주세요.
```

본인 대상 신고:

```text
본인이 작성한 콘텐츠는 신고할 수 없습니다.
수정 또는 삭제 기능을 이용해 주세요.
```

처리 결과:

```text
신고 검토가 완료되었습니다.
운영 정책에 따라 필요한 조치를 진행했습니다.
```

제재 통지:

```text
운영 정책 위반으로 콘텐츠가 제한되었습니다.
결정에 동의하지 않는 경우 30일 이내에 이의제기를 요청할 수 있습니다.
```

## 다음 구현 항목

- `moderation_action` 적용 API 추가: `HIDE_REVIEW`, `DELETE_REVIEW`, `RESET_PROFILE`, `SUSPEND_MEMBER`
- 리뷰 숨김 상태 컬럼 추가: 삭제와 임시 숨김을 분리
- 회원 작성 제한 상태 추가: 제한 대상 기능과 만료 시각 저장
- 신고 결과 알림 추가: 신고자와 피신고자에게 서로 다른 수준의 알림 전송
- 이의제기 테이블/API 추가
- 차단 기능 추가: 댓글/프로필 페이지가 생기기 전까지는 보류 가능

S3 이미지 처리 파이프라인 — 인터랙션 다이어그램

AS-IS (현재 구조) vs TO-BE (변경될 구조) · 업로드 · 조회

AS-IS

현재 구조

단일 버킷 · 서버 검증 없음 · CDN 없음 · 이미지 상태 없음

업로드 이미지 등록 흐름

sequenceDiagram participant C as 클라이언트 participant BE as Backend participant S3 as S3 단일 버킷 participant DB as PostgreSQL C->>BE: ① presigned URL 요청 (mimeType) BE-->>C: ② presigned URL + awsKey 반환 C->>S3: ③ PUT 원본 파일 직접 업로드 Note over C,S3: ⚠ 서버 검증 없음 — MIME·크기 클라이언트 선언에 의존 S3-->>C: 200 OK C->>BE: ④ POST 이미지 등록 (awsKey, mimeType) BE->>DB: ⑤ INSERT imageFile (awsKey 저장) DB-->>BE: 저장 완료 BE-->>C: 200 OK

조회 이미지 응답 흐름

sequenceDiagram participant C as 클라이언트 participant BE as Backend participant DB as PostgreSQL participant S3 as S3 단일 버킷 C->>BE: GET /stores/{id}/images BE->>DB: SELECT awsKey (상태 필터 없음) DB-->>BE: awsKey 목록 반환 BE-->>C: S3 직접 URL 목록 반환 Note over BE,C: https://s3.ap-northeast-2.amazonaws.com/{bucket}/{key} C->>S3: 이미지 GET (S3 직접 접근) S3-->>C: 이미지 데이터
TO-BE

변경될 구조

staging / final 버킷 분리 · 서버 검증 + 리사이즈 · 비동기 파이프라인 · CloudFront CDN

업로드 이미지 등록 흐름

sequenceDiagram participant C as 클라이언트 participant BE as Backend participant ST as S3 staging participant DB as PostgreSQL participant PIPE as img-pipeline participant FN as S3 final C->>BE: ① presigned URL 요청 BE-->>C: ② staging presigned URL + awsKey C->>ST: ③ PUT 원본 파일 ST-->>C: 200 OK C->>BE: ④ POST 이미지 등록 (awsKey) rect rgb(219, 234, 254) Note over BE,DB: HTTP 요청 스레드 (동기) BE->>DB: ⑤ INSERT imageStatus = PENDING DB-->>BE: commit 완료 BE-->>C: ⑥ 200 즉시 반환 end rect rgb(237, 231, 255) Note over BE,FN: img-pipeline 스레드 · @Async(imageProcessingExecutor) BE-)PIPE: ⑦ 비동기 트리거 (commit 직후) PIPE->>ST: 파일 다운로드 ST-->>PIPE: 파일 데이터 Note over PIPE: USER 요청은 매직바이트 검증 수행 (ADMIN은 스킵) alt 검증 실패 (USER only) PIPE->>ST: 원본 삭제 (DeleteObject) PIPE->>DB: UPDATE imageStatus = FAILED else JPEG · PNG 처리 (검증 통과) PIPE->>PIPE: Thumbnailator 리사이즈 (max 1280px) PIPE->>FN: PutObject (동일 awsKey) PIPE->>ST: 원본 삭제 (DeleteObject) PIPE->>DB: UPDATE imageStatus = DONE else WebP · HEIC 처리 (리사이즈 미지원) PIPE->>FN: CopyObject (동일 awsKey) PIPE->>ST: 원본 삭제 (DeleteObject) PIPE->>DB: UPDATE imageStatus = DONE end end

조회 이미지 응답 흐름

sequenceDiagram participant C as 클라이언트 participant BE as Backend participant DB as PostgreSQL participant CDN as CloudFront CDN participant FN as S3 final C->>BE: GET /stores/{id}/images BE->>DB: SELECT awsKey WHERE imageStatus = DONE DB-->>BE: DONE 상태 awsKey 목록 반환 Note over DB,BE: PENDING · FAILED 이미지는 응답에서 제외 BE-->>C: CDN URL 목록 반환 Note over BE,C: https://cdn.bbanggut.com/{awsKey} C->>CDN: 이미지 GET alt 캐시 히트 (Edge Cache) CDN-->>C: 즉시 이미지 응답 else 캐시 미스 CDN->>FN: Origin Fetch FN-->>CDN: 원본 파일 CDN-->>C: 이미지 응답 (이후 엣지 캐시 저장) end

변경 요약

AS-IS vs TO-BE 핵심 차이점

항목 AS-IS TO-BE
S3 버킷 단일 버킷 원본 그대로 저장, presigned URL 하나 staging + final 분리 검증·리사이즈 완료 후 final 이관, 원본 삭제
파일 검증 없음 MIME은 클라이언트 선언값만 신뢰 매직바이트 검증 USER 업로드에만 적용 (JPEG · PNG · WebP · HEIC)
리사이즈 없음 원본 크기 그대로 서빙 Thumbnailator JPEG·PNG max 1280px / WebP·HEIC는 CopyObject
이미지 상태 없음 PENDING → DONE / FAILED ImageFile·Banner 테이블에 image_status 컬럼 추가
업로드 응답 DB INSERT 완료 후 응답 DB PENDING 저장 후 즉시 200 반환, 이미지 처리는 비동기
비동기 처리 없음 @Async(imageProcessingExecutor) corePool=2 · maxPool=5 · queue=50
이미지 서빙 S3 직접 URL CDN 없음 CloudFront CDN URL 엣지 캐싱, origin S3 직접 노출 차단
공개 API 노출 업로드된 모든 이미지 노출 imageStatus = DONE 이미지만 노출 (PENDING 은닉)
awsKey 단일 버킷 내 경로 그대로 사용 staging · final 두 버킷에서 동일 awsKey 유지 → DB 컬럼 변경 불필요

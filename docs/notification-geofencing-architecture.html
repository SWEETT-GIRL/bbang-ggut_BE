1핵심 설계: 왜 이벤트 기반 지오펜스인가

3PostGIS 깊이 보기 ⭐

3-1. 위치 컬럼 — geography(Point, 4326)

// Store.java
@Column(nullable = false, columnDefinition = "geography(Point, 4326)")
private Point location;   // org.locationtech.jts.geom.Point (JTS)
  • geography 타입: 위경도를 지구 타원체 위 좌표로 보고 거리 계산이 자동으로 미터(m) 단위. 지구 곡률을 반영해 정확.
    ↔ geometry는 평면 좌표라 거리가 "도(degree)" 단위 → 미터 변환 별도 필요.
  • Point: 단일 좌표점. 4326 = WGS84(GPS 표준) SRID.
  • ORM: Hibernate Spatial + JTS(org.locationtech.jts) 매핑.

3-2. 쿼리 ① — 지오펜스 후보 (반경 3km 내 구독 가게, 거리순 20개)

SELECT
  s.id   AS "storeId",
  s.name AS "storeName",
  ST_Y(s.location::geometry) AS "latitude",    -- 위도 추출
  ST_X(s.location::geometry) AS "longitude",   -- 경도 추출
  ST_Distance(                                  -- 실제 거리(m) → 정렬용
    s.location,
    ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)::geography
  ) AS "distanceMeters"
FROM subscribed_store ss
JOIN store s ON ss.store_id = s.id
WHERE ss.member_id = :memberId
  AND s.status = 'ACTIVE'
  AND ST_DWithin(                               -- 반경 필터 (인덱스 사용)
        s.location,
        ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)::geography,
        :candidateRadius                        -- 3000.0 (m)
      )
ORDER BY "distanceMeters" ASC
LIMIT 20;

3-3. 쿼리 ② — 진입 검증 (구독 + 반경 내인지 재검증)

enter 보고가 오면 그 가게가 내 구독 가게이고 요청 좌표가 설정 반경 안인지 확인. 클라 좌표를 신뢰하지 않는 위변조 방어선.

SELECT EXISTS (
  SELECT 1
  FROM subscribed_store ss
  JOIN store s ON ss.store_id = s.id
  WHERE ss.member_id = :memberId
    AND s.id = :storeId
    AND s.status = 'ACTIVE'
    AND ST_DWithin(
          s.location,
          ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)::geography,
          :radius            -- 사용자 설정 반경 (R100~R1000)
        )
);

ST_MakePoint(lng, lat)좌표점 생성⚠️ 경도(X), 위도(Y) 순서 — lat, lng로 넣으면 엉뚱한 위치

Advisory Lock — 동시성 제어

iOS region monitoring은 같은 enter를 2~5회 짧은 간격으로 발화한다. 동시에 서버에 도달하면 중복 푸시가 나갈 수 있어 (memberId, storeId) 단위로 트랜잭션 락을 건다.

// 두 ID를 64bit 키 하나로 결합
long lockKey = (memberId << 32) | (store.getId() & 0xFFFFFFFFL);
if (!storeNotificationRepository.tryAdvisoryXactLock(lockKey)) {
    return; // 다른 트랜잭션이 같은 키 처리 중 → silent skip
}
SELECT pg_try_advisory_xact_lock(:key)   -- non-blocking, 트랜잭션 종료 시 자동 해제
  • pg_try_advisory_xact_lock: 즉시 시도(non-blocking). 이미 잠겨 있으면 false → 대기 없이 skip.
  • _xact_: 트랜잭션 스코프 → 커밋/롤백 시 자동 해제 (명시적 unlock 불필요).
  • 테이블 락이 아닌 애플리케이션 레벨 논리 락이라 가볍다.

5FE 지오펜스 등록 전략 (iOS 20-region 한계)

iOS는 동시에 모니터링 가능한 region이 하드 리밋 20개. 그래서 가까운 19개 가게 + pivot region 1개 전략을 쓴다.
flowchart TD Trigger["앱 시작 / 설정 변경 / ~500m·5분
locationRefreshTask"] --> RG["refreshGeofencesFromBackground(lat, lng)"] RG -->|"GET /alarm/geofence-candidates"| BE["BE: 3km 내 구독 가게
거리순 + 설정 반경"] BE --> Slice["가까운 19개 선택
MAX_STORE_REGIONS"] Slice --> Over{후보 > 19?} Over -- Yes --> Pivot["pivot region 추가
radius = max(최원거리×1.1, 500m)
notifyOnExit=true"] Over -- No --> Reg["가게 region만"] Pivot --> Start["startGeofencingAsync(regions)"] Reg --> Start PivotExit["사용자가 pivot 밖으로 이동"] -.exit.-> Trigger
  • pivot region: 사용자를 둘러싼 큰 원. enter 알림용이 아니라 exit 트리거 전용 (notifyOnEnter:false, notifyOnExit:true). 벗어나면 새 위치 기준으로 region 목록을 다시 짠다 (Apple 공식 샘플 패턴).
  • pivot 반경: 가장 먼 가게까지 거리 × 1.1, 최소 500m (haversine 계산).
⚠️ 트러블슈팅 — PAC trap 크래시
geofence 콜백 안에서 startGeofencingAsync()를 호출하면 EXTaskService가 실행 중인 자기 자신을 재등록하며 use-after-free → PAC trap 크래시 발생.
해결: region 갱신을 enter 콜백에서 분리해 별도 locationRefreshTask(500m/5분)에 위임. enter 콜백은 "보고"만, region 재등록은 "위치 갱신 태스크"만 담당하도록 책임 분리.

층위치방어 대상
1차FE geofenceTask같은 프로세스 즉시 중복 + cold-start 후 중복 (60s TTL)
2차BE advisory lock서버에 동시 도달하는 요청(경쟁 조건) 직렬화

SecureStore 실패 등으로 FE dedup이 새도 BE 2·3차가 받쳐준다 (방어선 다중화).

7핵심 설계 포인트 요약

① geography(Point,4326)

위경도 → 미터 단위 거리. 지구 곡률 반영.

② ST_DWithin + ST_Distance 분리

인덱스 타는 반경 필터로 좁히고, 좁혀진 행만 거리 정렬.

③ 위치 위변조 방어

클라 좌표 불신 — 서버가 ST_DWithin으로 반경 재검증.

④ advisory xact lock

iOS 중복 enter를 (member,store) 단위로 직렬화.

⑤ pivot region

iOS 20-region 한계를 exit 트리거로 우회.

⑥ PAC trap 회피

콜백 내 재등록 금지 — 책임 분리로 크래시 해결.

9내가 맡은 역할 (발표용 — 직접 채우기)

담당 영역: (예: 백엔드 지오펜스 + PostGIS 공간 쿼리 설계)

설계 기여:

  • PostGIS geography(Point,4326) 기반 반경 검색 — ST_DWithin(인덱스 필터) + ST_Distance(정렬) 분리로 성능 확보
  • 클라 좌표 위변조 방어용 서버측 거리 재검증 게이트
  • pg_try_advisory_xact_lock으로 iOS 중복 enter 동시성 제어

트러블슈팅:

  • iOS enter 2~5회 중복 → FE 60초 dedup + BE advisory lock + 일일 중복 3중 방어
  • (FE) geofence 콜백 내 재등록 → PAC trap 크래시 → 책임 분리로 해결

결과: 서버 폴링 없이 이벤트 기반 동작, 인덱스 기반 공간 쿼리로 빠른 반경 검색
